# Architecture

Implemented through M7, plus the LaTeX-body migration (packaged as a Windows one-folder build): workshop shell, shared pipeline, all eight tasks with their output layouts, Efficient (local text conversion) with caching and scan handling, and bounded recovery with actionable errors. Package root: `src/late_night_workshop/` (internal id; the app's display name is Late Night Pal). The proposed full plan is in `components.md` and `PROJECT_MAP_AND_MILESTONES.md`; this file lists only what exists.

Pipeline order (`generation.generate`): validate parameters and paths → LaTeX + destination preflight → prepare inputs (original or local text; scan decisions go back to the UI, and Cancel ends here with zero API calls) → resolve task → **one** Gemini request (JSON metadata + one `latex_code` body per document) → validate the bundle contract → check each document (static LaTeX rules, task content) → compile every PDF in a restricted lualatex process in a temp dir and check page counts → publish (all or nothing). The only extra Gemini requests, each announced in the status: one retry after a network error, one bundle repair after a failed contract check, and **at most one targeted repair per failed document** (unsafe or incomplete LaTeX, compile error, too many pages); documents that passed are never regenerated. Publish failures never call Gemini.

**Ownership.** Gemini owns document content and LaTeX layout (the body between `\begin{document}` and `\end{document}`). Python owns document identity (roles, days, `document_id`, title and subtitle placement), expected roles and counts, filenames and paths, the preamble and package allowlist, validation, compilation, page counts and publication.

## Gemini client and validation

| File or symbol | What it does |
| --- | --- |
| `gemini_client.py` · `generate_content(task, sources)` | One Interactions API call, model `gemini-3.8-flash` (or `GEMINI_MODEL`). The key comes from `GEMINI_API_KEY` in the environment, `./.env`, or (packaged) a `.env` beside `Late Night Pal.exe`. Originals (PDF) go inline as `document` items, each preceded by a `Source i: <source_id>` text item, with fingerprints rechecked. Text sources become one text item per file (`text_source_item`): `Source i: <id> (text extracted locally…)` with `[<id> - page N]` / `[<id> - slide N]` markers and `[end of <id>]`. One request can mix both. 50 MB total cap. Returns untrusted `{raw_text}`. Key-free `GeminiError` codes: `missing_key`, `api_quota`, `api_auth`, `api_model`, `api_limit` (HTTP 400: input, output or schema too large or complex; no verified numeric limit is known, so the API's own rejection is reported), `api_network`, `api_error` |
| `validation.py` · `validate_bundle(raw, task, sources)` | Bundle contract: each document is `{role, day, title, latex_code}` (non-empty string). Rejects the whole bundle on a wrong role set or count, a missing or duplicate (day, role), identical notes on two days, or an allocation that doesn't cover days 1..N, names an unknown source or leaves a source unused. Assigns `document_id` (`schedule`, `day-01-notes`, …) |
| `validation.py` · `document_problems(doc, task, sources)`, `latex_problems(code)` | Per-document checks, phrased for Gemini: `FORBIDDEN_COMMANDS` (preamble, `\input`/`\include`/`\includegraphics`, `\write`/`\openin`/`\read`, `\directlua` and other Lua, `\csname`/`\UseName`/`\expandafter`, `\catcode`, `\makeatletter`, `\ExplSyntaxOn`, `\usetikzlibrary`, …) used as commands **or** environment names, the `^^` notation, a 200 000-character cap; the schedule names every `Day N`; the file guide names every exact source label (after undoing `\_`). `parse_document_repair(raw)` reads a repair's `{latex_code}` |

Debug first: drop one document from a fixture bundle → `invalid_response` naming the missing role and day.

## Renderer and publisher

| File or symbol | What it does |
| --- | --- |
| `rendering.py` · `check_runtime()` | Resolves `lualatex` or raises `missing_latex`; called before any Gemini call |
| `rendering.py` · `ALLOWED_PACKAGES` | The one package allowlist: amsmath, amssymb, mathtools, siunitx, mhchem (version=4), booktabs, array, multicol, enumitem, xcolor, tikz. The templates load exactly these after the fixed fontspec/geometry/parskip setup, and the prompt lists them |
| `rendering.py` · `render_bundle(bundle, task, work_dir, subtitle, on_document, names)` | Compiles every document (it does not stop at the first failure) and returns `{records: [{document_id, role, day, temp_path, page_count, seconds}], failures: {document_id: {code, message, problem, log}}}`. `compile_document` fills the template (`<<PACKAGES>>`, escaped one-line `<<TITLE>>`, escaped `<<SUBTITLE>>`, raw `<<BODY>>` = `latex_code`), copies `guard.lua`, and runs up to two lualatex passes (the second only when LaTeX asks for a rerun; 180 s timeout each), then deletes byproducts so only the PDF stays (about 3–7 s per PDF with the packages). A compile failure keeps `problem` = the first `!` error lines with their `l.N` context (sent to Gemini in the repair) and copies the log to `%LOCALAPPDATA%\late_night_workshop\logs\`. With `max_pages`, the **compiled PDF's** page count (pypdf) decides: over the limit is a `page_limit_exceeded` failure. Daily PDFs' subtitles list only that day's `allocation.source_ids` |
| `rendering.py` · `run_sandboxed(args, cwd, timeout)` | Runs the compiler under the isolation described in LaTeX isolation below |
| `templates/guard.lua` | Runs in the preamble after the packages and before the body. Lua `io.open`/`io.lines`/`dofile`/`loadfile`/lualibs `io.loaddata`… and TeX `\input`/`\openin` (`find_read_file` callback) may read job files and, elsewhere, TeX/font files by extension only, so user documents and `.env` are refused. File changes (`os.remove`, `lfs.mkdir`, …) are allowed only inside the job folder; `os.execute` and `io.popen` are disabled; images only come from the job folder; the guard's callbacks cannot be removed and `debug` is cleared |
| `templates/document.tex`, `templates/cheat-sheet.tex` | Python-owned preamble: fontspec + Latin Modern, with fallback to Cambria / Segoe UI Symbol, geometry, the allowlisted packages, then `\maketitle` (document) or a one-line header (cheat sheet: 10 pt, 1.2 cm margins; Gemini chooses columns and type size) |
| `outputs.py` · `publish(rendered, task, destination, root)` | Checks IDs and count, maps names from the layout only (`relative_output_paths`). Single: `O_EXCL` claim of `name.pdf`, `name (2).pdf`, …. Folders: everything is copied into a hidden `.lnp-staging-*` sibling, then `os.rename` to `Folder`, `Folder (2)`, … (never replaces); staging is removed on failure |

## LaTeX isolation

Generated LaTeX is treated as untrusted, executable-like input: a prompt injection in a source file could ask Gemini for hostile code. Probed on this PC before the change: with only `-no-shell-escape`, a body could read any file the user can read (`\input{C:/…}` or Lua `io.open`) into the PDF, and could see `GEMINI_API_KEY` (`os.getenv`; `load_dotenv` puts it in the app's environment, which the compiler inherited). Writes outside the job folder and program launches were already refused by MiKTeX. `--safer` is not usable: fontspec fails under it. Layers now:

1. **Static check** (`validation.latex_problems`) before any compile; violations go to that document's one repair.
2. **Separate restricted process** (`rendering.run_sandboxed`). Generated LaTeX is never compiled in the app process. It runs with the job temp folder as cwd, `-no-shell-escape -halt-on-error`, an environment reduced to `ENV_KEEP` + `MIKTEX_*` (no key), and a 180 s timeout per pass. On Windows the process starts suspended inside a job object: `ActiveProcessLimit` 1 (no child programs), 2 GB memory, no clipboard, desktop or global-atom access, killed when the job handle closes.
3. **Read guard** (`templates/guard.lua`) for anything the static check misses.

Verified (`tests/test_latex_pipeline.py` · `Sandbox`): a body that uses Lua `io.open` and `\openin` on a file outside the job folder, and `os.getenv("GEMINI_API_KEY")`, prints neither the file nor the key.

**Known limits (not solved in this scope).** This is not an OS sandbox such as an AppContainer or a separate user account: lualatex still runs as the user. The denylist and guard are best effort against TeX's macro language. A body that defeats both could read files with TeX-like extensions (`.tex`, `.sty`, fonts…) outside the job folder, or fill the temp disk until the timeout. The PDF stays local and is published only after all checks pass. The compiler has no network module, so it sends nothing anywhere.

## Generation and errors

`generation.py` · `generate(request, on_progress, deps)` returns `{status, output_root, paths, warnings, timings: {gemini_s, render_s, publish_s}, documents: [{document_id, page_count, render_s}]}` or `{status: "error", error: envelope}`. `deps` swaps `check_runtime` / `generate_content` / `render_bundle` / `publish` for stubs. `decide_inputs(decisions) -> {source_id: "process_original"|"cancel"}`: anything other than process_original for every pending source returns `{status: "cancelled"}` before any API call; otherwise preparation reruns with those `original_overrides`. Without a `decide_inputs` callback (the CLI), the job is cancelled. Bounded recovery: `ask_gemini` retries once only after `api_network` (quota, auth and limit errors are not retried). `validated` sends one `REPAIR_PROMPT` request for a failed bundle contract (the problem, the task prompt and the previous JSON, without re-sending sources) and fails with "… (also after one repair attempt)". Then every document goes through `document_problems` and `render_bundle`. Each failed document (static problem, `compile_failed` or `page_limit_exceeded`) gets one `repair_document` request: `DOCUMENT_REPAIR_PROMPT` with the problem (LaTeX error lines or page count), the task prompt and that document's `latex_code` only, schema `tasks.REPAIR_SCHEMA` `{latex_code}`, no sources. The repaired body is rechecked and recompiled once; a second failure ends the job with its code (`invalid_response`, `compile_failed` with the log path, `page_limit_exceeded`) and "(also after one repair attempt)". Publish errors never call Gemini. Rendering happens in a `TemporaryDirectory` that is always removed. `__init__.py` · `AppError` subclasses give `{code, stage, message, source_id, retryable, details}`.
