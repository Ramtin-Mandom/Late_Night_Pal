# Component handoff guide

## Start here and component index

Start with `architecture.md` for implemented components and `workflow.md` for the working generation flow. Follow `AGENTS.md` (also referenced by `CLAUDE.md`). The active organizer specification is `PHASE_2_PROJECT_MAP_AND_MILESTONES.md`; consult it for full algorithms and acceptance rules. `PROJECT_MAP_AND_MILESTONES.md` is historical Phase 1 intent: its eight-hour schedule and blanket organizer exclusion are no longer active Phase 2 instructions.

The checkout contains Phase 1 application source, prompts, templates, README, dependencies, and packaging. Existing below means verified by source inspection, not freshly runtime-tested. Phase 2 P2-M1 is done: organizer contracts plus a Wrap planner (`P/organizing.py`, no mutation), the selection contract below, and a passed Chrome feasibility probe (`P/downloads.py`, evidence under Downloads). P2-M2 is done: Organize/Make me modes, shared file+folder selection, Remove controls, Refresh and Make me eligibility. P2-M3 is done: Delete, Rip, Wrap, Copy and Paste run through `organizing.execute_plan()` with per-item outcomes, `workshops.reconcile()` and the clipboard/Recycle Bin adapters. Super Wrap stays disabled until P2-M4; P2-M4 onward are not implemented. A file's existence alone does not prove integration.

All paths are repository-relative. **P** in tables and prose abbreviates the existing `src/late_night_workshop/` directory; expand it when opening files. New paths and APIs are explicitly proposed.

## Entry/UI: capture work and render results

Actual entry route: `__main__.main()` → `ui.run_app()` → `Window.generate()` → `generation.generate()`. `Window` and `Worker` are local classes inside `run_app()`, not module-level imports. Reuse `Window._workshop_page()`, `browser_clicked()`, `refresh()`, `refresh_selected()`, `current_parameters()`, and `job_finished()`. The Qt-free `ui.build_request(state, task_id="summary", parameters=None, efficient=False)` copies the request at Generate time. UI consumes returned paths, not guessed filenames.

P2-M2 UI (in `run_app()`'s `Window`): **Organize** / **Make me** buttons below Selected Inputs switch a `QStackedWidget` (default Make me); switching calls only `refresh_selected()`, so selection and every Make me widget value persist. Organize shows Delete, Rip, Wrap, Copy, Paste and Super Wrap (disabled, tooltip `SUPER_WRAP_PENDING`) and Rip's helper text `RIP_HELP`. P2-M3 flow in `Window.organize(action)`: `capture_request()` first (before any dialog), Wrap's name dialog / `clipboard_read()` for Paste, `plan_action()` (an `OrganizeError` is shown with its paths and nothing runs), Copy → `clipboard_put()` only, a confirmation listing `preview()` for Delete and for a cut Paste, then `OrganizeWorker` runs `execute_plan()` on a `QThread`. `organize_finished()` → `workshops.reconcile()` → `clipboard_after()` → `refresh()` → `describe_outcomes()` status. Organizer buttons and Generate are disabled while either kind of job runs. Each browser row is a widget: a checkbox (`Select <name>`) calls `toggle()`; a flat name button opens a folder (`open_folder()`) or toggles a file. Selected Inputs rows show `[folder]`/`[missing]` plus the relative path and a **Remove** button (`Remove <rel> from selection`) that calls `remove_selected()` → `workshops.deselect()`. Row clicks defer their rebuild with `later()` (a zero-delay timer) because the clicked widget is destroyed by the redraw. **Refresh** beside Up calls `refresh_clicked()` → `workshops.prune()` and names anything it removed in the status. `refresh()` only redraws and never prunes. Preserve the existing eight-task behavior, supported generation inputs, Efficient default/note, progress, and layouts.

Capture sources, destination, and parameters before launching any action, following `build_request()`; later navigation cannot redirect work. Disable conflicting operations while paths are in use. Widgets, dialogs, selection presentation, chip drop events, result/progress rendering, and clipboard calls requiring Qt GUI access stay on the UI thread. Scans and filesystem operations belong off it. Existing `Worker.run()` invokes generation on a `QThread`; `Worker.decide()` signals `answer_decisions()`/`choose_for()` and waits on an Event. Reuse this worker/UI handoff; no worker opens a dialog. `job_finished()` calls `quit()` before `wait()`.

UI changes widgets and delegates path/selection truth to workshop helpers. Debug first: inspect a request snapshot and `refresh_selected()` when eligibility is wrong. Organizer needs its own partial-outcome status text: generation's “Nothing was saved” message is incorrect after a partially successful move.

## Workshop: canonical paths and shared selection

`workshops.open_workshop(path)` returns `{root: Path, current: Path, selected: set[Path]}` and updates recents; `create_workshop(path)` creates a real folder. Reuse `browse(state, folder=None)`, `relative(state_or_root, path)`, `selected_sorted(state)`, `is_inside(root, path)`, `is_link(path)` (symlink/junction, shared with `organizing`), and `validate_paths(root, destination, paths)`. `toggle_selection(state, path)` accepts any existing file or folder inside the workshop, refuses the root and links, and returns a boolean. `browse()` hides dot entries and resolved out-of-root links; it never changes the selection. Limitation: `browse()` lists in-root links by their resolved target, so a link's target (not the link) is what gets selected; `organizing` preflight still rejects link paths.

**Selection contract (P2-M1, implemented in P2-M2).** `state["selected"]` in `workshops.py` is the only canonical selection: resolved absolute paths, shared by Organize and Make me, untouched by navigation or mode switches. The UI keeps no second copy.

| UI event | Call | Effect |
| --- | --- | --- |
| Click a folder name | `browse(state, folder)` | Navigate only; selection unchanged |
| Row checkbox on a file or folder; clicking a file's name | `toggle_selection` | Add/remove one canonical path |
| Remove button beside a Selected Inputs entry (both modes; accessible name = relative path) | `deselect(state, path)` | Discard by canonical key even when missing or outside the current view; never touches the file |
| Refresh button | `prune(state)` then `browse()` | Drop selected paths that no longer exist (reported in the status), move `current` to its nearest surviving folder |
| Executor outcomes | `reconcile(state, outcomes)` | Remap completed moves, drop completed deletions, keep everything else |

Make me eligibility: `inputs.generation_blockers(paths)` → `{path: reason}` for entries that are missing, folders, unsupported types (not in `inputs.SELECTABLE`) or unreadable; `ui.make_me_status(state)` → `{ok, blockers, message}`. `refresh_selected()` shows blocked rows in red (reason in the tooltip), the full message in the red note above Generate, and enables Generate only when `ok` and no job runs; `generate()` also returns early unless `ok`. Removing a blocker changes only the selection; task, Days, Folder name, style and Efficient are not reset. Generation keeps its file-only `validate_paths()` recheck (a folder in a request fails as `unreadable_input` before any model call). Snapshots: Generate uses `ui.build_request()`; organizer buttons will call `organizing.capture_request(state, action, parameters)` at click time (Wrap/Super Wrap add `folder_name` from the dialog, but root, destination and sources come from the click). It copies every selected entry, folders and off-screen paths included, into a new list, so later selection changes or navigation cannot alter it. Check: `python -m unittest tests.test_selection -v`.

`reconcile()` uses `remap_paths()`: completed `moved` entries and anything inside them get the new path, completed `deleted` entries and their contents leave the selection, and failed, unattempted and `copied_source_kept` entries stay as they are. The current folder follows a move or falls back to its nearest surviving folder. P2-M4/M5 must keep: selection changes only through `workshops` helpers, `capture_request()` at click time, no pruning outside Refresh, and Make me's own eligibility check.

Existing persistent state is `%LOCALAPPDATA%/late_night_workshop/recents.json`, via `app_data_dir()` (with a non-Windows fallback). `validate_paths()` returns canonical `{root, destination, paths}` and checks readability/containment; it is generation groundwork, not full organizer preflight. Debug first: compare `state['selected']`, `selected_sorted()`, and `browse()` output before changing UI highlights.

## Inputs/converters: preserve the generation boundary

Actual signature: `inputs.prepare_inputs(root, selected_paths, efficient=False, capabilities=None, original_overrides=frozenset())`, returning `{sources, decisions, warnings}`. Supported UI inputs are PDF, PPTX, DOCX, TXT, MD. Efficient off uses supported originals (currently PDF); PPTX/DOCX fall back to local text with a named warning. Efficient on extracts locally; TXT/MD always use text. No OCR. An empty PDF page or average below 40 non-whitespace characters/page triggers a decision when original processing is supported. Unsupported original plus unusable text fails with an export hint.

Source records contain `source_id`, `filename`, `relative_path`, `mime_type`, `fingerprint` (`sha256:` plus digest), `size`, `mode`, `text_parts`, `original_path`, `cache`. Source ID is workshop-relative POSIX path, so rename changes it. Original mode has a path and empty text parts; text mode has `{unit, number, text}` records (pages/slides one-based; document number `None`). Pending decisions may have placeholder sources; generation resolves them before transport. Decision fields include `source_id`, `filename`, `code`, `reason`, `units`, `unit_kind`, `choices`.

Reuse `converters.supported(path)` and `convert(path, data)` → `{converter, units, cache}`. Converter owns successful content-addressed caches under `app_data_dir()/conversions/`, with converter version/options in the key. Debug first: `_low_text_units()` or returned units/cache status. These generation-specific input restrictions must not gate organizer actions.

## Registry/prompts: exact task contracts

Reuse `tasks.tasks_for()`, `validate_parameters(task_id, parameters)`, `safe_folder_name(name, default)`, `assemble_prompt(task_id, params, sources)`, and `resolve_task(request, sources)`. `safe_folder_name()` checks Windows names/length, but trims surrounding whitespace and supplies a default on empty input. Organizer/tag validation must add their empty/cancel/trailing-space behavior instead of assuming this helper alone satisfies the Phase 2 rules.

`assemble_prompt()` uses `resource_path()` to read the task's `prompt_file` and replace `{days}`, read `prompts/` plus `STYLES[language_style]`, then read `prompts/format.md`. Assembly order: source index → task body → style → shared format. All prompt paths are inside P. Single-file styles are Technical/Standard/Simple; planning tasks use Standard. `resolve_task()` returns `task_id`, `label`, normalized `parameters`, `prompt`, `response_schema`, `expected`, `layout`, `template`, `max_pages`. Daily expected fields are `days`, `roles_per_day`, `document_count`; other tasks use `days` (or `None`), `roles`, `document_count`.

| Task ID | Prompt under `P/prompts/` | Roles / count | Output under captured destination |
| --- | --- | --- | --- |
| `schedule` | `schedule.md` | schedule, file-guide, checklist / 3 | `Study Schedule/{schedule,file-guide,checklist}.pdf` |
| `daily-study-plan` | `daily-study-plan.md` | notes, sample-questions, checklist per day / 3 × Days | `Daily Study Plan/Day NN/{notes,sample-questions,checklist}.pdf` |
| `checklist` | `checklist.md` | checklist / 1 | `checklist.pdf` |
| `notes` | `notes.md` | notes / 1 | `notes.pdf` |
| `summary` | `summary.md` | summary / 1 | `summary.pdf` |
| `answer-key` | `answer-key.md` | answer-key / 1 | `answer-key.pdf` |
| `cheat-sheet` | `cheat-sheet.md` | cheat-sheet / 1 | `cheat-sheet.pdf`; cheat-sheet template, max_pages 1 |
| `sample-questions` | `sample-questions.md` | sample-questions / 1 | `sample-questions.pdf` |

Planning parameters: positive integer `days` (not bool), optional `folder_name`; Single file: `language_style`. Empty planning folder names resolve to the defaults above; publication may add collision suffixes. Debug first: inspect a resolved task/assembled prompt without calling Gemini.

## Gemini transport: untrusted content, no retry loop

Actual callables include `get_capabilities()`, `model_name()`, `text_source_item(i, source)`, `generate_content(task, sources, purpose="initial")`. `purpose` currently does not change behavior. `_source_items()` attributes text with page/slide markers or sends inline PDF document bytes after fingerprint recheck; changed originals raise `source_changed`. The local cumulative content cap is 50 MiB; do not infer verified token/schema limits from it. `generate_content()` uses `client.interactions.create()` with the resolved JSON schema and returns `{raw_text, usage: {}}`. Generation does not expose usage in its result.

The checkout defaults to `gemini-3.8-flash`, overridable by `GEMINI_MODEL`; this is a source fact, not a fresh availability claim. `_client()` loads runtime credentials; organizer work needs no secret inspection. Client owns transport and sanitized SDK failures; **generation**, not client, owns network retries and content recovery. Debug first: source item construction or sanitized failures with a stub. No Gemini call is needed for Phase 2 organization.

## Generation/validation: request → checked bundle → result

Actual signature: `generation.generate(request, on_progress=lambda event: None, deps=None, decide_inputs=None)`. The third positional argument is **deps**, not `decide_inputs`; use the latter by keyword. Request fields: `workshop_root`, `destination`, `selected_paths` (absolute strings), `task_id`, `parameters`, `efficient`. Daily parameters can be `{"days": 2, "folder_name": ""}`; Summary parameters `{"language_style": "Standard"}`. `ui.build_request()` captures root/current/selection, copies parameters, and normalizes Efficient to bool.

Order: parameter/path checks → runtime/destination preflight → capability/preparation → decision callback and re-preparation → task resolution → Gemini → validation → all temporary renders → publication. Missing choices or anything other than `process_original` cancels before a model call. `deps` replaces `check_runtime`, `generate_content`, `render_bundle`, `publish`; other boundaries remain real. Reuse this injection seam for focused regressions, not a second pipeline.

Raw JSON schema requires `documents`, `allocation`, and each document's `role`, integer `day`, `title`, `blocks`. **Wire/prompt non-daily day is 0**, including schedule documents; `validation.validate_bundle(raw_text, task, sources)` normalizes it to Python `None`. The validator does not enforce raw non-daily day equals 0. Daily days stay integers 1…Days. IDs equal role for non-daily documents and `day-01-notes`, etc. for daily ones. Validated return is `{documents, allocation, sources}`, with deterministic IDs and sorted source IDs.

Only four block kinds work: `heading {text}`, `paragraph {text}`, `list {items: [string]}`, `question {label, text}`; all have `kind`. No heading-level field, table block, math block, or Markdown renderer is implemented. `_clean_blocks()` strips text, filters blank/nonstring list items and empty text blocks, requires question label/text, and rejects unknown kinds or an empty resulting document. It is not strict validation of every malformed field.

Validation checks exact role/day sets, duplicate daily pairs, identical daily notes, allocation day/source coverage, schedule Day N headings, and exact source IDs in the file guide. It does not prove topic quality or compare answer labels against extracted questions. For sample questions, `_label_answers()` finds a heading beginning with “answer”, takes preceding question labels, and converts an unlabelled paragraph/list tail to labelled question blocks only if counts match and no question/heading is in the tail. Already-labelled answers stay supplied; mismatched counts are not automatically paired. Answer-key validation requires a labelled block when there is more than one block. Printed-label preservation and FLAGGED uncertainty are prompt requirements; correctness against the source remains a content check.

Success: `{status: 'ok', output_root, paths, warnings, timings, documents}`; document summaries contain `document_id`, `page_count`, `render_s`. Error: `{status: 'error', error, timings}`. Cancelled: `{status: 'cancelled', timings}`. `AppError.envelope()` supplies `code`, `stage`, `message`, `source_id`, `retryable`, `details` (optional log text under `log`). Progress is `{stage, message, source_id: None}` with preparing/awaiting_input/generating/validating/rendering/publishing.

Generation owns temp-directory lifetime and bounded recovery: one schema repair; one cheat-sheet condensation with direct revalidation; one `api_network` retry per `ask_gemini()` invocation, including a recovery request. Compile/publish failures do not cause model repair. Debug first: remove day 2's checklist from a canned bundle; validation names the missing pair and failed repair never reaches publishing.

## Renderer: formula text and local compilation

Actual helpers: `check_runtime()`, `escape()`, `one_line()`, `blocks_to_latex()`, `compile_document()`, `render_bundle(bundle, task, work_dir, subtitle="", on_document=None, names=None)`. Templates: `P/templates/document.tex`, `P/templates/cheat-sheet.tex`. Renderer changes temporary PDFs/byproducts and `app_data_dir()/logs/` diagnostics; generation owns temp cleanup. It never chooses final paths or calls Gemini.

Formula trace: `prompts/format.md` fixes `Math mode = plain`; no code parameter changes it. Its mention of LaTeX notation does not establish implementation support. JSON decoding yields text; validation retains accepted strings without a math parser; `blocks_to_latex()` calls `escape()` on text, labels, and items. Backslashes, dollars, braces, underscores, and carets are escaped. `d = v * t` stays plain text, while `\( ... \)`, `\[ ... \]`, and LaTeX commands print literally. Do not claim interpreted formulas or restricted-math support.

Compiler is lualatex: two `-no-shell-escape -halt-on-error` passes/document, 180-second timeout per pass, then byproduct cleanup. Render records are `{document_id, role, day, temp_path, page_count, seconds}`. Cheat sheet tries 8.5pt then 7.5pt before `page_limit_exceeded`; generation owns condensation. Compile failures name the intended output and diagnostic log. Debug first: inspect `blocks_to_latex()` with `50%`, `A&B`, or formula text; actual compilation is a later implementation check, not part of this edit.

## Publisher: generation outputs only

Actual helpers: `check_destination(destination, workshop_root)`, `relative_output_paths(task, rendered)`, `publish(rendered, task, destination, workshop_root)`. Publisher checks unique IDs/count, not a separate exhaustive ID/role contract; upstream validation supplies correct roles/IDs. Registry normalizes folder names. A single PDF claims its name with `O_EXCL`; planning PDFs copy into hidden `.lnp-staging-*` siblings before final rename. Free-name suffixes are ` (2)`, ` (3)`, etc.; failed folder staging is cleaned. Return is `{output_root, paths}` with absolute strings. No source is moved and no cache/log/LaTeX byproduct is published.

Do not apply generation's all-or-nothing output promise to arbitrary organizer moves. Reuse naming/containment groundwork, while organizer owns its full destination validation and partial reporting. Debug first: `relative_output_paths()` with a two-day fixture; during implementation, publish fixture PDFs twice to check collision behavior.

## Organizer and OS adapters: planning, execution, outcomes

`P/organizing.py` owns planning, execution and the OS adapters; the UI only orchestrates. Entry points: `capture_request(state, action, parameters)` → `{action, workshop_root, destination, sources, parameters}`; `plan_action(request)` → `{action, root, destination, create_folder, items: [{source, destination, kind, op, identity}], batch_id?, skipped?}` or `OrganizeError(code, message)` whose `.paths` name the problem; `execute_plan(plan, ops=None)` → `{action, status: ok|partial|failed, outcomes, created, removed, batch_id, skipped}`; `preview(plan)` / `label(root, path)` for dialogs and status. Each outcome is `outcome(item, status, change, error)`: `{source, destination, kind, status: completed|failed|unattempted, change: moved|copied|deleted|copied_source_kept|None, error}`. `ops` replaces `move`/`copy`/`recycle`/`rmdir` for tests.

| Action | Planner | Executor |
| --- | --- | --- |
| Wrap | Raw name check, then a new folder under the captured current folder; existing name in any case refused | `mkdir` (fails if it appeared since planning), then move each item; if nothing moved, only the empty new folder is removed |
| Rip | Selected folders only (files ignored; none → `no_folders`); children go to the folder's current parent; any clash with an existing entry, the wrapper's own name or another child is refused | Move each child, then `rmdir` the now-empty wrapper (`deleted`) |
| Delete | Sources + `recycle_available()` (`SHQueryRecycleBinW` on the drive) | `recycle()` = `SHFileOperationW` with `FOF_ALLOWUNDO` + `FOF_WANTNUKEWARNING`, then checks the entry is gone |
| Copy | Sources only | None: the UI calls `clipboard_put()` (file list + Preferred DropEffect COPY + own marker); nothing is copied |
| Paste (copy) | `clipboard_read()` paths; external entries allowed, but an entry that is or contains a link is refused; next free `name (2).ext` per item; folder into itself/descendant refused | Verified copy (`open(..., "xb")` / `copytree`, file count and bytes compared); a failed copy removes only what it created |
| Paste (cut) | Local paths only (UNC → `unsafe_cut`); not already in this folder; same naming/into-itself rules; `batch_id` = hash of the ordered source list | Saves a per-item record in `%LOCALAPPDATA%/late_night_workshop/organizer-cuts.json` (atomic replace) **before** the first move, updates it after every item; cannot save → nothing moves |

Shared checks: `check_folder_name(raw)` runs on the text as typed (None = cancel, blank, padded) **before** `tasks.safe_folder_name()`; `preflight_destination()`; `preflight_sources()` (absolute, existing, inside the workshop, not the root, no symlink/junction between root and the path, selected descendants of a selected folder dropped); `check_not_into_self()`; `check_unique_targets()` (case-insensitive). OneDrive placeholders are reparse points but not links. Immediately before each mutation `_recheck()` repeats: the source still exists, is not a link, is still inside the workshop (paste sources excepted), still has the planned `identity` (type, size, mtime), and the destination does not exist and sits in an in-workshop, non-link folder. Nothing is ever overwritten.

Moves: `os.rename` on one volume; across volumes copy → verify → remove the source. A copy that verified but whose source could not be removed is `failed` / `copied_source_kept`; both paths are reported and kept, and selection keeps the old path. Execution stops at the first failure: later items are `unattempted` and untouched.

External cut protocol: the app performs each move itself and **never writes any acknowledgment** (`Performed DropEffect` / `Paste Succeeded`) back, so the source application never deletes anything; the clipboard is cleared only when every item moved. Pasting the same cut again is a retry: completed items are skipped (even if a new file now sits at an old path), the reserved destinations are reused, and the plan is refused (`cut_changed`) if a remaining source changed or vanished or its reserved destination is now taken. It is also refused if a previous item ended `copied_source_kept` (`cut_needs_review`), if it targets another folder (`cut_elsewhere`), or when everything is done (`cut_done`). Unsafe requests are rejected before any write, never turned into a copy. `clipboard_after()` also remaps or drops our own copied references that a later action moved or deleted.

Checks: `python -m unittest tests.test_organizing tests.test_selection tests.test_executor -v` (17 tests: Wrap→Rip Coursework/Batch, Rip collision and files-only refusal, a Wrap target appearing after planning, same-folder copy suffix and into-itself refusals, the three-item cut A done / B failed / C unattempted with record, no full acknowledgment and safe retry, retry refusal on a taken reserved destination, UNC cut rejection, `copied_source_kept`, and one real Recycle Bin delete of a temp file).

Rip keeps its name and helper text: “Move each selected folder’s contents up one level.” Executor moves immediate children to the wrapper's **current parent**, removes only the empty wrapper, and ignores ordinary selected files. No original-location history exists. Wrap `Lectures/a.pdf` and `Labs/b.pdf` as `Coursework/Batch`; Rip yields `Coursework/a.pdf` and `Coursework/b.pdf`, not the original paths. Debug first: captured wrapper parent and collision preflight. Refer to the Phase 2 plan for all action rules.

## Super Wrap: proposed pure planner

Proposed `P/super_wrap.py` maps names to destinations without filesystem/UI calls. Organizer supplies filenames and outer-folder name, validates the full returned mapping, then executes it. Preserve extensions; selected existing folders move intact as opaque entries. Use the Phase 2 plan's exact underscore-token grouping, minimum two-file buckets, prefix removal and termination rules; do not invent a second algorithm here.

Debug fixture: `Cal_1_assignment_1.pdf`, `Cal_1_Note_1.pdf`, `Cal_1_assignment_2.pdf` become `<outer>/Cal_1/assignment/{1,2}.pdf` and `<outer>/Cal_1/Note_1.pdf`. Note's bucket is a singleton, so its name stays `Note_1`. Check this pure mapping before exercising the executor.

## Tags: proposed folder metadata owner

Proposed `P/name_tags.py` owns `%LOCALAPPDATA%/late_night_workshop/organizer.json`, reusing `workshops.app_data_dir()` and atomic replacement writes. Store up to six active chips per canonical folder plus separate per-name counter history. UI emits creation/removal/drop events; tag logic supplies a safe one-file rename request/counter reservation; executor returns confirmed outcomes. Preserve extension, skip occupied numbers, and do not advance on ordinary failure/cancel. Persist reservation before finalizing rename, release on ordinary failure; reconcile interruption (a gap is acceptable). Report storage errors instead of claiming saved success. Storage/recovery APIs are proposed.

Only confirmed outcomes alter metadata: remap moved/renamed folder paths and descendants; copying does not clone tags. Folder-tree Delete clears active tags **and counter history** only for confirmed deleted folders. Rip remaps surviving child folders/descendants to actual paths, preserves their state, and clears the wrapper's own state only after confirmed removal.
